# 第 2.1 阶段技术开发文档｜基础设施 + 账号权限 + 知识库 RAG

> 配套文档：学工Buddy-一页PRD-V0.1、技术适配声明、AI Agent 产品 Vibe Coding 通用技术栈手册
> 本文档只覆盖阶段 2.1。后续 2.2（文稿生成 Agent）和 2.3（表格台账 Agent）另开文档。

## 一、阶段目标

- **交付范围**（对齐 PRD 第三/四/五节）：
  - 模块 4：账号与权限——邀请码注册/登录、个人账号隔离
  - 模块 1：私有知识库 RAG——文档上传/向量化/问答（流式 SSE）、引用原文出处
  - 模块 5（部分）：全局免责提示、操作日志
- **阶段产物**：
  - 可独立启动的后端 API 服务
  - 知识库问答最小验收界面（单个 HTML，`static/` 目录）
- **验收标准**：
  - 邀请码注册成功率 100%
  - 文档上传 → 向量化 → 问答引用原文，全链路可跑通
  - 流式问答以 SSE 正确收尾（done/error）
  - mock 测试通过 + 真实模型冒烟通过
- **明确不做**（留到 2.2/2.3）：
  - 文稿生成 Agent（谈话记录、班会方案等模板生成）
  - Excel 台账批量处理
  - 学院共享知识库（先做个人库，共享库在 2.2 加）
  - 自定义模板管理界面（后端 API 的模板 CRUD 可在 2.2 做）
- **本阶段打通的主链路**：
  ```
  用户注册/登录 → 上传政策文档 → 文档向量化入库 
  → 在对话界面提问 → SSE 流式返回答案 + 原文出处
  ```

## 七、API 设计

### 通用约定
- 前缀：`/api/v1`
- 认证：登录后返回 JWT token，后续请求带 `Authorization: Bearer <token>`
- 错误格式：`{"error": {"code": "ERROR_CODE", "message": "中文描述"}}`
- 所有接口返回类型均为 `application/json`，SSE 接口返回 `text/event-stream`

### 7.1 认证

#### POST /api/v1/auth/register
- 请求：`{"email": "str", "password": "str", "invite_code": "str"}`
- 校验：邮箱格式、密码≥6位、邀请码有效且未使用
- 响应 201：`{"user_id": 1, "email": "..."}`
- 错误：`INVALID_EMAIL` / `WEAK_PASSWORD` / `INVALID_INVITE_CODE` / `EMAIL_EXISTS`

#### POST /api/v1/auth/login
- 请求：`{"email": "str", "password": "str"}`
- 响应 200：`{"access_token": "jwt...", "token_type": "bearer", "user": {...}}`
- 错误：`INVALID_CREDENTIALS` / `USER_DISABLED`

#### GET /api/v1/auth/me
- 需要认证
- 响应 200：`{"id": 1, "email": "...", "role": "...", "created_at": "..."}`

### 7.2 知识库

#### POST /api/v1/kb/upload
- 需要认证
- 请求：`multipart/form-data`，字段 `file`（支持 pdf/txt/docx）
- 校验：文件类型、大小 ≤20MB、安全文件名
- 后台处理：保存文件 → 分段 → 向量化 → 更新状态
- 响应 201：`{"document_id": 1, "filename": "...", "status": "uploaded"}`
- 错误：`FILE_TOO_LARGE` / `UNSUPPORTED_FORMAT` / `INVALID_FILENAME`

#### GET /api/v1/kb/documents
- 需要认证
- 查询参数：`?status=done`（可选筛选）
- 响应 200：`{"documents": [{...}], "total": 10}`

#### DELETE /api/v1/kb/documents/{doc_id}
- 需要认证，只能删自己的文档
- 响应 200：`{"message": "已删除"}`
- 错误：`NOT_FOUND` / `FORBIDDEN`

#### GET /api/v1/kb/chat
- 需要认证
- 查询参数：`?q=如何申请奖学金&conv_id=1`（conv_id 可选，不传则创建新对话）
- 响应：SSE 流
  ```
  event: chunk
  data: {"content": "根据《学生"}

  event: chunk
  data: {"content": "手册》..."}

  event: done
  data: {"conv_id": 1, "message_id": 5, "content": "完整答案", "citations": [{"doc_name": "学生手册.pdf", "chunk_text": "..."}]}
  ```
- 错误：SSE error 事件
  ```
  event: error
  data: {"error": {"code": "KB_EMPTY", "message": "知识库为空，请先上传文档"}}
  ```

#### GET /api/v1/kb/conversations
- 需要认证
- 响应 200：`{"conversations": [{"id": 1, "title": "...", "created_at": "..."}]}`

#### GET /api/v1/kb/conversations/{conv_id}/messages
- 需要认证
- 响应 200：`{"messages": [{...}]}`

### 7.3 管理（Admin）

#### POST /api/v1/admin/invite-codes
- 需要认证 + admin 角色
- 请求：`{"count": 5}`（一次生成几个）
- 响应 201：`{"codes": ["ABC123", "DEF456", ...]}`

#### GET /api/v1/admin/invite-codes
- 需要认证 + admin 角色
- 响应 200：`{"codes": [{...}]}`

#### GET /api/v1/admin/logs
- 需要认证 + admin 角色
- 查询参数：`?page=1&size=50`
- 响应 200：`{"logs": [{...}], "total": 100}`

## 八、Prompt 设计

### RAG 问答 Prompt（`services/prompts/rag_qa.py`）

```python
RAG_QA_SYSTEM = """你是一位高校学工领域的专业助手，名叫"学工Buddy"。
你的回答基于用户上传的文档内容。

## 规则
- 只根据提供的文档片段回答问题，不要编造来源中没有的信息
- 如果文档中没有相关信息，诚实回复"根据已上传的文档，暂未找到相关信息"
- 回答使用正式、专业的语言，符合高校行政风格
- 涉及学生、思政、危机相关话题时，禁止给出处置决策，仅提供流程参考
- 回答末尾附上引用的文档名称

## 禁止
- 禁止编造政策条款、金额、日期等具体数据
- 禁止给出心理诊断或危机处置决策
- 禁止在文档无相关信息时强行回答"""

RAG_QA_USER_TEMPLATE = """## 参考文档
{documents}

## 用户提问
{question}

请基于上述参考文档回答用户提问。"""
```
