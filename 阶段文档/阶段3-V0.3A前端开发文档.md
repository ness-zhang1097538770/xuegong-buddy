# 阶段 3 前端开发文档｜V0.3-A 四页面

> 日期：2026-09-22
> 范围：在 V0.1 内容生产前端（知识库问答/文稿/台账/常用网站）基础上，新增 V0.3-A 副驾四页面，并按 PRD 第四节重排导航分组。
> 依据：PRD V0.3、《前端技术栈手册》、阶段 2.4 后端文档、现有 frontend 代码。

## 1. 本阶段目标

辅导员登录后，在「副驾」分组里完成四件日常事：看驾驶舱待办（副驾首页）、记一次谈话并让它自动归档+跟进（谈话记录仪）、翻一个学生的叙事档案（一人一页）、一句话生成班会全套材料（通知变材料）。原有内容生产能力（知识库/文稿/台账）保留并下沉到「生产」分组。

## 2. 范围

### 本阶段包含（按子阶段交付）

| 子阶段 | 路由 | 页面 | 对接后端 |
|---|---|---|---|
| 1 | `/` | 副驾首页（驾驶舱）：Hero 4 数字 + 待办清单 | `GET /home/summary`、`POST /home/todos/{id}/resolve` |
| 2 | `/talks` | 谈话记录仪：左侧叙事时间轴 + 右侧录入/AI 初稿 | `GET/POST /talks`、`POST /talks/draft`、`POST /talks/{id}/close-follow` |
| 3 | `/students` | 一人一页：列表 + 详情抽屉（时间轴/交接包） | `GET /students`、`GET /students/{id}`、`GET /students/{id}/handover` |
| 4 | `/notice` | 通知变材料：一句话 → 六件套 + 历史 + 下载 | `POST /notice/generate`、`GET /notice/tasks`、`GET /notice/{id}`、`GET /notice/download/{id}` |
| 全局 | — | 导航重排（副驾在上/生产在下）+ 知识库问答迁至 `/kb` | — |
| 补充 | `/experts` | 专家智能体（5 位辅导员专家流式对话，会话回看/删除） | `GET/POST /experts/*` |

### 本阶段不包含

- 事务审批（奖助/违纪）、查寝降级版、大赛陪练（V0.3-B）
- 语音 ASR 输入（V0.4）
- 学工部大盘 / 风险雷达（V0.4）
- 上线部署（阶段 4）
- 前端单元测试补齐（本项目 V0.1 起即未配置 vitest，沿用 lint/typecheck/build + 浏览器验证；记为已知项，不阻塞交付）

## 3. 用户流程

```
登录 → 副驾首页（看 4 数字 + 待办，点待办内联处理）
  → 谈话记录仪：选学生 → 填要点 → AI 初稿 → 人工修改 → 保存（即归档 + 可选跟进待办）
  → 一人一页：列表筛选 → 打开抽屉看时间轴 → 导出交接包
  → 通知变材料：一句话 → 生成六件套 → 预览三版通知 → 下载 Word
生产分组：知识库问答 / 文稿 / 台账（V0.1 能力不变）
```

## 4. 页面状态矩阵

| 页面 | 初始 | 加载 | 空 | 运行 | 成功 | 失败 | 恢复 |
|---|---|---|---|---|---|---|---|
| 副驾首页 | Hero + 待办 | 骨架/加载中 | 「今日无待办」 | 内联处理 loading | 待办消失、数字更新 | 错误提示 | 刷新重新拉取 |

## 5. 接口契约

沿用阶段 2.4 后端 API，前端经 `/api/*` 同源代理。新增前端 API 封装：

- `homeApi.summary()` / `homeApi.resolveTodo(id)`
- `talkApi.list()` / `talkApi.create(...)` / `talkApi.draft(...)` / `talkApi.closeFollow(id, conclusion)`
- `studentApi.list(...)` / `studentApi.detail(id)` / `studentApi.filters()` / 交接包走 `downloadFile`
- `noticeApi.generate(...)` / `noticeApi.tasks()` / `noticeApi.task(id)` / 下载走 `downloadFile`

错误结构：新增端点统一 `{"error":{"code","message"}}`，`request()` 已兼容；老端点 `{"detail"}` 兼容保留。

## 6. 实现方案

- 复用现有设计系统（蓝 `#2563eb` + 青 `#0ea5a4` 渐变、卡片 16px 圆角、Inter + PingFang SC）。
- 导航改「分组」结构：`nav-items.ts` 输出 `NAV_GROUPS`（副驾 / 生产 / 其他）；桌面侧栏分组渲染，移动端底部导航横向滚动全量可达。
- 知识库问答页从 `/` 迁至 `/kb`（组件不变，仅改路由）。
- 副驾首页 Hero 严格 ≤160px：仅身份 + 周期 + 4 数字，禁止图表/轮播/宫格。
- 所有 AI 输出（谈话初稿、通知材料）带「草稿」水印 + 人工复核提示（沿用全局免责声明 + 页面内提示）。

## 7. 验收标准

- 自动检查：`npm run lint`、`npm run typecheck`、`npm run build` 全过。
- 浏览器验证（桌面 1280px + 移动 390px）：四页均可操作、无横向溢出、Console 无报错。
- 真实后端联调：副驾首页 4 数字真实计数；谈话保存即归档（一人一页可查）；通知变材料真实生成六件套并可下载。
- 合规：谈话/通知输出均标注草稿水印与复核提示。

## 8. 风险与回退

- 风险：通知变材料生成约 26s，前端需明确「生成中」状态并防重复提交。
- 风险：一人一页 200 人列表渲染性能；先按后端分页 size=50 处理。
- 回退：V0.1 四页面与临时验收页均保留，不影响已交付能力。
