# 技术适配声明｜学工 Buddy

> 基于 PRD《学工Buddy-一页PRD-V0.1》与《AI Agent 产品 Vibe Coding 通用技术栈手册 V2.1》
> 生成日期：2026-09-20

## 1. 产品形态判断

- **产品类型与核心任务**：垂直场景 AI 办公 Agent SaaS。三大核心能力——私有知识库 RAG 问答、文稿生成（思政模板库）、表格/台账批量处理。
- **核心交互**：
  - 文稿生成 / 台账处理：一次生成 + 导出（上传 → AI 生成 → 下载 Word/Excel → 用户本地复核）
  - 知识库问答：多轮对话（流式输出，引用原文出处）
- **开发路径**：**后端先行**。文稿和台账是"提交→返回结果→下载"模式，可独立通过 API 验证；知识库问答需要一个最小对话界面来验收流式效果，用单个 HTML 临时验收页面即可。
- **当前阶段范围**：阶段 2 后端 MVP，涵盖 PRD 的五大模块——
  - 模块 1：私有知识库 RAG
  - 模块 2：文稿生成 Agent
  - 模块 3：表格/台账 Agent
  - 模块 4：账号与权限
  - 模块 5：系统基础设置
- **明确不做**：学生端、校内系统对接、消息自动发送、心理诊断、移动端 APP（与 PRD MVP 范围一致）

## 2. 采用的默认方案

| 默认方案 | 采用原因 |
|---|---|
| Python 3.12 + FastAPI + Pydantic | 手册标准后端栈，与线上运行时一致 |
| pytest | 双层验收体系的 mock 测试层 |
| `/api/v1` 前缀 | 新建公开 API 的标准前缀 |
| `.env` + `.env.example` | 密钥不入仓库的默认方式 |
| 后端先行开发路径 | 核心能力可通过 API 独立验证，交互以提交/下载为主 |
| 知识库问答用临时 HTML 验收界面 | 仅用于验收流式效果，不提前铺开正式前端 |

## 3. 触发的按需模块

| 模块 | 触发需求 | 本阶段引入 |
|---|---|---|
| **SQLite + SQLAlchemy + Alembic** | 多用户账号、角色权限、操作日志、对话历史——需要关系型数据库 | ✅ 是 |
| **Chroma（持久化模式）** | 私有知识库 RAG——文档分段向量入库，语义检索 | ✅ 是 |
| **python-docx** | 文稿生成 Agent 导出 Word（谈话记录、班会方案、评语等） | ✅ 是 |
| **openpyxl** | 表格/台账 Agent——读取学生 Excel、批量生成评语、回写表格 | ✅ 是 |
| **pypdf** | 知识库上传 PDF 政策文件解析 | ✅ 是 |
| **SSE（流式输出）** | 知识库问答实时展示生成内容 | ✅ 是 |
| **本地文件目录 `data/`** | 上传文档、生成文件存储 | ✅ 是 |

**本阶段不引入的模块**：OCR（只处理可复制文字 PDF）、任务队列（MVP 单用户量不需要）、对象存储（先用本地目录）。

## 4. 偏离或暂缓的默认方案

| PRD 原建议 | 实际方案 | 原因 | 影响 | 重新评估条件 |
|---|---|---|---|---|
| 基于 Dify 快速搭建 | Python + FastAPI 自建 | Dify 低代码平台难以实现批量 Excel 回写、自定义权限模型、多模块 Agent 编排等定制需求；全栈自建 2 个月可交付 | 需自行实现 RAG 管道和 Agent 编排（非不可行，手册有完整指引） | 如 2 周内核心能力无法跑通，可重新评估 Dify 作为 RAG 模块的替代 |
| （未指定）上线企业认证 | MVP 阶段个人开发者认证 | 企业认证耗时数天至数周，MVP 小范围内测个人认证够用 | 月费上限 300 元，正式上线前需升级 | 内测用户超 20 人时升级企业认证 |

## 5. 强制底线检查

| 检查项 | 状态 | 说明 |
|---|---|---|
| 密钥与隐私 | ✅ 通过 | API Key 仅存后端 `.env`，不入仓库；学生敏感信息仅存用户知识库，不用于模型训练 |
| 数据与任务可恢复 | ✅ 通过 | SQLite 持久化任务状态、对话历史、操作日志；进程重启后可恢复 |
| 输入输出校验 | ✅ 通过 | Pydantic 校验所有 API 输入输出；模型输出结构校验+宽容解析 |
| 错误与日志边界 | ✅ 通过 | 统一 `{"error": {"code", "message"}}` 格式；日志不记密钥和敏感原文；SSE 以 done/error 收尾 |
| 测试与真实模型验收 | 计划明确 | 第一层 mock 测试覆盖业务逻辑/解析器/状态流转；第二层真实模型冒烟每种调用契约至少一条完整链路；D2 验收标准待第一次冒烟时用 5-10 条样例定 |

3. ✅ **暂缓项是否影响验收**：暂缓了 Dify（改用自建）、企业认证（先用个人认证）。不影响 MVP 核心功能验收，不影响 2 个月交付目标。
