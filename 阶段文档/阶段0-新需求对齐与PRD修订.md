# 阶段 0 · 新需求对齐与 PRD 修订｜学工 Buddy

> 日期：2026-09-21
> 性质：无代码阶段（PRD 修订），阶段闸门是否表 N/A 项见文末

## 1. 背景

产品经理带来新需求文档《高校辅导员AI办公产品_方案想法》（定位讨论稿），要求对现有产品做功能增删改查。本阶段完成：差异分析 → 5 项决策卡确认 → 产出 PRD V0.3 修订稿。

## 2. 差异总览（新文档 vs 现有产品）

| 新文档核心主张 | 现有产品 | 判定 |
|---|---|---|
| MVP 三功能：谈话记录仪、一人一页、通知变材料 | V0.2 有谈心谈话、学生档案；文稿为通用版 | 前两个方向对齐需升级，第三个需新增 |
| 定位：辅导员个人副驾 Copilot | V0.2「内容生产+事务办理工作台」 | 口径需改 |
| 三个不要碰：学生端问答、查寝/请假/签到、纯 AI 心理测评 | V0.2 刚把查寝考勤、请假审批 PRD 为核心模块 | 直接冲突 |
| 双视角：辅导员端 + 学工部大盘 | 只有辅导员单端 | 缺另一半 |
| 卖「不出事」不卖「减负」 | 卖点是「写得快、办得快」 | 卖点需改 |
| 风险雷达放第二阶段 | 无 | 需补设计 |
| 冷启动：大赛陪练（个人付费） | 无 | 新增 |

## 3. 增删改查清单

**增（4）**：通知变材料、学工部大盘、大赛陪练、谈话记录仪语音输入
**删/降级（2）**：查寝考勤、请假审批（奖助/违纪审批保留）
**改（4）**：谈心谈话→谈话记录仪、学生档案→一人一页、定位/卖点口径、风险雷达补设计
**查/补强（2）**：合规红线完整写入（AI 不判定风险等级）、隐私红线复核

## 4. 决策卡结论（PM 已确认「按推荐」）

| # | 决策 | 结论 |
|---|---|---|
| Q1 | 查寝考勤 + 请假审批 | 降级为非卖点、挪后续批次；奖助/违纪审批保留 |
| Q2 | 大赛陪练 | 纳入产品做轻量版（个人付费冷启动） |
| Q3 | 学工部大盘 | PRD 定义、V0.4 交付 |
| Q4 | 语音输入 | 先文字闭环、ASR 后置 |
| Q5 | 定位口径 | 全面对齐「副驾 + 不出事 + 双视角」，产品名沿用「学工Buddy」 |
