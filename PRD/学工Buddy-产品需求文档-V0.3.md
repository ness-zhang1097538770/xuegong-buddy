# 学工Buddy 产品需求文档 V0.3

> 辅导员个人副驾 Copilot · 高校学工 AI 办公
> 版本 V0.3 ｜ 2026-09-21 ｜ 研发与验收依据
> 一句话定位：**不替辅导员做决定，只替辅导员记、写、提醒。**
> AI 输出仅为草稿，涉及学生、思政、危机材料必须人工复核。

---

## 执行摘要

学工Buddy V0.3 基于新需求文档《高校辅导员AI办公产品_方案想法》完成一次战略校准：产品从「内容生产 + 事务办理工作台」收敛为「**辅导员个人副驾 Copilot + 学工部大盘**」的双视角形态。

- **V0.1（已交付）**：解决「写得快」——知识库 RAG、文稿生成、台账处理、常用网站。
- **V0.2（本版取代）**：原「业务工作台 5 模块」按新战略重排——谈心谈话升级为「谈话记录仪」、学生档案升级为「一人一页」、新增「通知变材料」；查寝考勤与请假审批降级为非卖点增强。
- **V0.3 本版核心**：**谈话记录仪、一人一页、通知变材料、副驾首页** 四件套，对齐新需求文档 MVP 三功能 + 副驾入口。
- **卖点口径**：从「减负」改为「**关键时刻不掉链子 / 不出事 / 考核达标**」。

## 一、版本说明

### 1.1 变更背景

新需求文档《方案想法》给出三条战略判断，直接改变 V0.2 的取舍：

1. 现有玩家都在做「系统」和「学生端」，没人认真做「辅导员这个人的办公副驾」——**我们是副驾，不是系统**。
2. 三个红海不碰：学生端问答、查寝/请假/签到、纯 AI 心理测评。
3. 付费方是学工部，买的是「安全稳定 + 考核达标」，不是「减负」——**功能按减负设计，按不出事卖**。

## 二、产品定位与卖点

### 2.1 定位

> **一句话**：不替辅导员做决定，只替辅导员**记、写、提醒**。

形态必须是 **Copilot（AI 拟稿 + 人工确认）**，绝不能是 Autopilot。

### 2.2 卖点口径（全站统一）

| 维度 | 旧口径（V0.1/V0.2） | 新口径（V0.3） |
|---|---|---|
| 一句话卖点 | 写得快、办得快 | **关键时刻不掉链子** |
| 对学工部的说法 | 效率工具 | **风险防控 + 考核达标 + AI+思政成果** |
| 对辅导员 | 减负 | 领导要数据 30 秒给得出、家长问情况能说准、学生出事前已提醒 |

> 铁律：**减负是结果，不是卖点。** 功能按减负设计，按「不出事」卖。

## 三、用户结构（四方分离 + 双视角）

| 角色 | 是谁 | 真实诉求 | 产品给什么 |
|---|---|---|---|
| **使用者** | 一线辅导员（人均带 200–300 学生） | 别重复劳动、别背锅 | 记、写、提醒的副驾 |
| **付费方** | 学工部 / 信息化处 | 不出事、考核达标、有亮点 | 风险预警大盘 + 「AI+思政」成果 |
| **被服务方** | 学生 | 少填表、问题有人答 | （间接）响应更快、被关注 |
| **监管方** | 教育厅 / 43 号令 | 队伍专业化、工作可追溯 | 台账规范、可导出、可审计 |

**双视角落地**：辅导员端（个人副驾）+ 学工部端（全局大盘）。大盘 PRD 定义于本版，交付于 V0.4。

## 五、功能详述

### 5.0 保留功能（V0.1 内容生产，已交付，能力不变）

| 模块 | 要点 |
|---|---|
| 知识库 RAG | 私有知识库上传、流式问答 + 引用；本版增加「审批助手/谈话初稿」调用出口 |
| 文稿生成 Agent | 模板 + 变量 + 参考文件 → Word；本版被「通知变材料」复用 |
| 台账处理 Agent | Excel 上传 → 批量生成 → 下载；本版复用于学生/宿舍基础数据导入 |
| 常用网站 / 登录 | 4 类 12 站点；邀请码 + 邮箱注册，能力不变 |

### 5.1 模块一 · 副驾首页（驾驶舱）

**定位**：辅导员每天上班第一个打开的面板。只回答三个问题——我是谁、这段口径是什么、今天有几件事要办。

| 区域 | 内容 | 规则 |
|---|---|---|
| Hero 区 | 身份（姓名/学院/带班）+ 周期切换 + 4 个数字 | 高度 ≤160px；4 数字＝待我审批、待跟进谈话、今日异常宿舍、学业预警人数；点击直达对应模块并带筛选 |
| 待办清单 | 聚合审批待办、谈话跟进到期、查寝未处置、材料填报截止 | 每条带内联操作按钮，不二次跳转；逾期置顶 > 今日 > 未来 |
| 空状态 | 「今日无待办」 | 不塞推荐内容 |

**Hero 区明确禁止**：图表、轮播、公告、快捷入口宫格、天气、进度条。

**验收**：首屏 160px 内只出现身份/周期/4 数字；每条待办 ≥1 个可点按钮；单条审批从首页办完 ≤2 次点击。

### 5.2 模块二 · 谈话记录仪（谈心谈话升级）

**定位**：把「事后补假台账」变成「事中一句话留痕」。左边看历史、右边直接写，**录入即归档，归档即进档案，需要跟进自动回到待办**。

| 区域 | 占比 | 内容 |
|---|---|---|
| 左侧历史区 | 40% | 按学生聚合的叙事时间轴：时间/方式/主题/结论/是否跟进 |
| 右侧录入区 | 60% | 学生选择、谈话方式、主题标签、内容、结论、需要跟进开关、附件 |

**升级点（相对 V0.2）**：
1. **叙事性归档**：保存即写入该生「一人一页」的叙事时间轴，生成记录编号，无需二次归档。
2. **自动跟进待办**：打开「需要跟进」→ 默认 7 天后回待办（可改 3/14/30 天或自定义），连续 3 次未处理升级提醒至学院负责人。
3. **AI 初稿**：基于本次要点 + 该生历史生成记录草稿，标「草稿」水印，必须人工修改后保存。
4. **语音输入（后置，V0.4）**：语音 60 秒 → 规范台账（对象/类型/问题归类/处置/下一步/是否需上报）。

**合规边界**：❌ 不做心理诊断、❌ 不下危机结论；心理/危机/家庭变故类记录默认仅本人与学院负责人可见，越权访问留日志告警。

**验收**：保存即出现在该生档案；打开「需要跟进」保存后首页生成跟进待办；记录可闭环、可导出 Word。

### 5.3 模块三 · 一人一页（学生档案升级）

**定位**：辅导员打开就能回答「这孩子啥情况」。不是数据报表，是**叙事性档案**——这学生什么时候发生了什么、我们做了什么、下一步是什么。

| 分区 | 内容 |
|---|---|
| 基本信息 | 姓名/学号/班级/标签/风险分 |
| 学业与考勤 | GPA、出勤率进度条（保留 V0.2 进度条：GPA<2.0 红、出勤<90% 红） |
| **叙事时间轴** | 历次谈话、奖惩、资助、家庭特殊情况按时间聚合，可见「上次结论」 |
| **换届交接包** | 一键生成该生交接包（转专业/换届/离校场景） |
| 快捷动作 | 发起谈话、查看审批记录、加入关注 |

**升级点（相对 V0.2）**：从「进度条扫视报表」升级为「叙事时间轴 + 换届交接包」；进度条保留作扫视定位。

**合规边界**：❌ 不做人格标签化；敏感字段（心理/家庭经济/成绩）按角色脱敏。

**验收**：1280px 下一屏 12 行、行高 44px；打开抽屉再关闭，筛选/排序/滚动位置不丢；200 人首屏渲染 ≤1.5s；可一键导出交接包。

### 5.4 模块四 · 通知变材料（新增）

**定位**：传播性最强的一句话 demo。一句话主题 → 一次性产出全套材料，30 秒让人「哇」。

| 输入 | 输出（一次性打包） |
|---|---|
| 一句话：主题 + 时间 + 地点 + 对象（可选） | ① 通知文案三版（正式/群发/家长） ② 班会方案（PPT 大纲/案例/互动/主持词） ③ 签到表 ④ 纪要模板 ⑤ 自动归档 |

**实现**：复用 V0.1 文稿生成 Agent 模板引擎，新增「班会/通知」场景模板包。

**验收**：30 秒产出全套；三版文风区分明显；全部带「草稿」水印与复核提示；可归档至班级/学生档案。

### 5.5 模块五 · 事务审批（奖助/违纪保留，请假降级）

**定位**：审批时不来回翻学生信息。

| 类型 | 色条 | 状态 |
|---|---|---|
| 奖助（奖学金/助学金/困难认定/勤工助学） | 绿 #22c55e | **保留**（对应「困难生精准认定」预算科目） |
| 违纪（处分/通报/申诉） | 红 #ef4444 | **保留**（对应「安全稳定」预算科目） |
| 请假（病假/事假/离校） | 蓝 #2563eb | **降级**：挪 V0.3-B，非卖点 |
| 其他（走读/证明） | 灰 #e2e8f0 | 保留 |

**保留能力**：学生画像标签上卡、历史请假统计、影响课程清单、右侧常驻审批助手（风险提示 + 政策引用 + 常用语）、批准/驳回按钮始终由人点击、留痕。

### 5.6 模块六 · 查寝考勤（降级版，V0.3-B）

**定位**：从「核心模块」降为「工作台完整性增强」，**不作为卖点宣传**。

**保留能力**：三色网格总览（绿已查正常/红异常/灰未查）、底部异常名单打电话 + 一键生成违纪单、5 秒撤销、留痕。

**降级说明**：不投入卖点宣传与销售话术，功能按 V0.2 已设计的最小可用版本交付即可。

### 5.7 模块七 · 大赛陪练（轻量版，V0.3-B）

**定位**：冷启动切入口，个人付费（¥99–199/年），不占学校预算。

| 能力 | 说明 |
|---|---|
| 谈心陪练 | AI 扮演「有抵触情绪的贫困生 / 失恋学生 / 被诈骗学生」，陪练后自动复盘打分 |
| 案例分析 | 案例题自动生成分析框架（定性—归因—处置—反思） |
| 转化钩子 | 陪练后顺势推「你平时带班也用这个记台账吧」→ 转化核心产品 |

**实现**：复用现有对话 + 文稿能力，成本低，不引入新模型。

## 七、合规红线（完整写入 PRD，全站硬约束）

| 红线 | 产品设计约束 |
|---|---|
| 学生隐私（心理/家庭经济/成绩） | 支持私有化/校内部署；禁明文走公网大模型；脱敏后才可入训练 |
| 心理危机判定 | AI 只做**行为信号聚合与提示**，禁止输出「该生有自杀倾向」等结论；强制人工介入 |
| 行政行为决策权 | AI 只能**拟稿与材料整理**，决策与签字必须人工；保留「AI 建议 vs 最终决定」差异日志 |
| 43 号令履职责任 | 谈心谈话等面对面工作不得由 AI 替代，AI 只做记录与提醒 |
| 数据出境与等保 | 学校普遍要求等保三级；SaaS 版需明确数据存储地与合规声明 |
| AI 边界（通用） | 只提示不决策、必标草稿、可溯源（政策附原文出处）、留痕（AI 生成与人工修改分记） |

> 一句话原则：**AI 只做育人增量，不做替代变量。**
